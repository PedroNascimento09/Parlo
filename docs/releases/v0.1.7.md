# v0.1.7

Parlo now opens as a window of its own. Until today the interface was a page that `parlo` served locally and handed to your browser, which meant an address bar, a tab, a bookmark folder and a translation tool that looked like a website you had accidentally opened. This version ships `parlo-app`, a small native shell that opens the same screen in its own window, with its own icon and title bar, and starts and stops the translation engine for you. Double-click it and Parlo is running. Close it and Parlo is gone.

That sounds cosmetic and is not. A window owns its engine: it picks a free port, hands the local service a fresh token, waits until the engine answers, and shows the app only when it can actually translate. Nothing else on your machine can drift into that port by accident, and the engine cannot outlive the window — close the window, or let it crash, and the engine goes with it. No stray copy keeps a port open in the background until you find it in the task manager.

## What it feels like to use

You unzip the archive, double-click `parlo-app`, and a window appears immediately with a quiet starting screen: a pulsing mark and a line saying the engine is loading. That wait is real and it is not hidden — the engine loads its models in about eighteen seconds on the reference machine, and from the second run on nothing has to be downloaded, so nothing surprising happens between the double-click and the app. When the engine answers, the starting screen is replaced by the interface in the same window.

Once there, everything works the way it did: one card to speak into, the translated sentence underneath, the translated voice playing back, live mode for a conversation, captions for a meeting you would rather read, a panel that dubs a file, and settings that choose the language direction and the recogniser. The microphone is the machine's microphone, the audio goes to the engine in the same process tree, and nothing is uploaded.

If the engine ever fails to start, the window does not hang forever or die silently. After four minutes it replaces the starting screen with a plain explanation: close Parlo, open it again, and if it repeats, the two log files it names hold the reason. Both are in the system temporary folder, one for the window and one for the engine, and both are written even when Parlo is started by double-click and has no console to print to.

## What else changed

`parlo app` now opens the window when `parlo-app` sits beside `parlo`, and falls back to the browser when it does not, so the command keeps working in a source checkout that has not built the shell. `parlo install` copies both programs into the per-user folder and its Start Menu entry — or Linux desktop entry — opens the window rather than a console. The release archive carries three things now: `parlo`, `parlo-app` and the `parlo-engine` folder, and the engine folder still has to stay beside the two programs.

From a source checkout, `scripts/parlo-app.cmd` and `scripts/parlo-app.sh` build both programs and open the window, or you can run `cargo run --release -p parlo-app`.

## What was measured

The engine's cold start on the reference machine is unchanged at **18.1 s**, and the window waits exactly as long as the engine takes: it polls the local health endpoint and shows the interface the moment it answers 200, so the starting screen adds no fixed delay of its own. The handover was exercised on Windows 11 with the packaged engine: the window process and the engine process start together, the page loads inside the window, and killing the window process takes the engine down within a second, which was checked by looking for the process afterwards and finding none.

The reasoning behind the architecture is the same reason the page exists at all: the interface is one HTML screen talking to a loopback HTTP service, and a native shell is the thinnest thing that can present it as an app. It reuses the whole interface instead of forking a second one, and the same code runs on Windows, macOS and Linux through the system webview.

## Installing it

Download the archive for your system, unpack it, and double-click `parlo-app`. The first run offers the roughly 800 MB of models once, with a progress counter, and everything works offline afterwards. If you would rather have it somewhere permanent, run `parlo install` once: it copies `parlo`, `parlo-app` and the engine into your user folder and adds a menu entry that opens the window. `parlo uninstall` removes them and keeps the models unless you add `--purge`.

On Windows the window uses WebView2, which ships with Windows 10 and 11 as part of Edge, so there is nothing to install. On Linux it uses WebKitGTK and the archive has been built against it; on macOS the system webview is used as it comes. Only Windows has been run by hand so far. The shell compiles and is tested on all three platforms in CI, but it has not been opened on a Mac or a Linux desktop, and that is stated here rather than left for you to find out.

## What does not work yet

The window is not signed and not packaged as an `.msi`, `.dmg` or `.deb`, so the first launch is still an unzip and a double-click, and Windows SmartScreen will ask once whether you trust the file. There is no tray icon and no global shortcut: closing the window closes Parlo. The update button still replaces the `parlo` program underneath and asks you to reopen the window, which then picks up the new version, but the window program itself is not replaced by that button yet, so a release that changes only the shell would need a fresh download. There is no virtual microphone, so a call app still sees the system microphone. Only Portuguese and English have models, in both directions, and translation quality is machine quality.
