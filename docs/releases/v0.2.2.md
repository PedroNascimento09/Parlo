Parlo 0.2.2 repairs the updater. The previous version downloaded the new program and reported it installed while the running program still held its own file, so Windows refused the replacement and the version never changed.

## Highlights

- The new program replaces the old one after Parlo exits, never while it runs: a small script waits for the process, moves the file, and starts `parlo app` again on its own.
- The update shows real progress from the download itself, not a spinner: the percentage comes from the download's own meter, then unpacking, then the check that the program is there.
- **Restart now** appears after the unpack, for the case where Parlo does not come back by itself.
- **Install update** only appears when the release carries a build for this platform, and the box says so in a sentence when it does not.

## Measured

- Tests on the reference machine, Windows 11, Rust release build: **114** in `parlo-cli` and **77** in `parlo-core`, with `clippy -D warnings` and `fmt --check` clean.
- The archive this release replaces is the one the bar tracks: `parlo-windows-x86_64.zip`, **68.5 MB** on v0.2.1, downloaded from the release page.

## Install

Run `Parlo-Setup.exe` from this release once. The version you have cannot replace itself, because the fault is inside it; from 0.2.2 onwards the update runs inside the app, with progress and its own restart.

## Known limitations

- The replacement is a Windows batch script. If Windows refuses the move, the old version stays and starts again; the app does not verify the move afterwards and cannot report a refusal it did not see.
- The restart after the move is the last step of that script, so a machine that blocks it needs Parlo opened from the Start menu.
