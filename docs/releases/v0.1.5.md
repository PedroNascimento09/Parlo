Parlo now speaks in both directions on demand and starts with a double-click. The pair is chosen on the command line, and the launchers build once and then open the interface, so nothing has to be typed to use it.

## Highlights

- `parlo app`, `parlo serve`, `parlo listen` and `parlo translate` accept `--from` and `--to`, validate the codes, and refuse a pair that cannot work instead of silently translating the wrong way.
- `scripts/parlo-app.cmd` on Windows and `scripts/parlo-app.sh` on Linux and macOS build on first run and then open the interface, so a person without a terminal can start it by double-clicking one file.
- The models panel from v0.1.4 keeps the first run usable: it lists what is installed, what is missing, and downloads the rest from the page.

## Measured

- English to Portuguese through the cascade on Windows 11, 4 threads: 6.33 s of input produced 4.21 s of Portuguese audio, with the language pair taken from `--from en --to pt`.
- The warm steady state is unchanged: 420.7 ms per segment, p95 485 ms, over the thirty minute soak.
- Cold start remains about 18 s per process; the direction is fixed for the life of a process, so switching it starts a new one.

## Install

```bash
cargo build --release -p parlo-cli
./target/release/parlo app
```

On Windows, double-click `scripts/parlo-app.cmd` instead. `parlo update` installs the next release over the running copy.

## Known limitations

- One direction per process. Changing `--from` or `--to` means restarting the app, and a fresh start pays the cold start again.
- The launchers need the Rust toolchain on the machine, because they build the binary the first time; an installer that ships a ready binary is still the next step.
- The page was exercised through its endpoints, not clicked through in a browser by the maintainer; the launchers were checked for syntax, not run from a double-click.
- Windows is the only platform validated end to end, Portuguese and English only, machine translation quality.
